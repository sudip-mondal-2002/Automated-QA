# Bessemer Tech Catalyst challenge alignment

This document maps the September 2026 Aivar Innovations problem statement to the current repository. The supplied PDF is marked confidential, so it is not copied into this public repository. This is a requirements traceability summary, not a substitute for the organiser's original document.

## Challenge outcome

Autonomous QA accepts a web application URL as its sole required input and coordinates the complete lifecycle without a human handoff between stages:

```text
URL -> discover -> Planner -> coverage gate -> Generator -> execute -> Healer/triage -> report
```

The public developer experience is the installed `$autonomous-qa` skill in the application repository. **Console** is the optional loopback interface for composing that request and reviewing file-backed decisions; it is not a second runner.

## Must-have traceability

| Problem-statement requirement | Implementation | Judge-visible evidence |
| --- | --- | --- |
| URL is the sole required input | `orchestrate --url`; all other fields have defaults or are optional | Enter only **Target URL** in Console and show the generated request |
| Planner explores meaningful flows beyond happy paths | `src/planner-agent.js`, bounded route-owned planning, deterministic fallback | `test-plan.json`, planned-flow list, planner source, error/edge flows |
| Coverage is evaluated before generation | `src/coverage.js`, 12-rule gate, bounded replan/escalation | Coverage score, blocking/advisory gaps, gate decisions in Console |
| Generator produces executable tests with live validation | `src/generator.js`, semantic spec generation, predicate compilation, locator/assertion validation | Generated YAML/replay artifacts, validation counts, explicit `UNVERIFIED` rather than invented assertions |
| Tests run and failures invoke healing/triage | `src/replay.js`, `src/execution.js`, `src/healing.js`, `src/locator-chain.js` | Fresh browser evidence; one equivalent retry for drift; genuine product failure remains red |
| Final quality report | `src/reporter.js`, schema-validated `report.json` and `report.md` | Scenarios, outcomes, healer actions, remaining gaps, untested risks, trace |

Planner, Generator, and Healer are specialised capability seats coordinated by one meta-agent. They are not three long-running services: Planner receives bounded evidence packets, Generator is constrained by schema and live validation rails, and Healer receives only a failed action plus unchanged expectations and may attempt one evidenced equivalent target.

## Explicit scope boundary

The challenge excludes production-scale hosting, CI/CD integration, cross-browser matrix testing, complete production coverage, and manually authored executable scripts. This repository keeps those outside the MVP. Semantic intent may be reviewed by a person, but executable browser artifacts are generated by the pipeline.

## Evaluation-criteria evidence

| Criterion | Weight | What to demonstrate |
| --- | ---: | --- |
| Functionality and completeness | 30% | One URL enters; a fresh report exits with no manual scripting between stages |
| Innovation and originality | 20% | Coverage-gated replanning, compatibility-checked history, conservative healing, defect classification |
| Technical implementation and code quality | 20% | Schemas, immutable context packets, bounded concurrency, source hashes, tests, honest blocked states |
| User experience and demo clarity | 15% | Install one skill, work only in the app project, use Console to compose and inspect |
| Business impact and feasibility | 10% | Reviewable tests/evidence without adding a QA framework or coordination burden to the app |
| Presentation | 5% | Follow the timed script in `demo.md` and explain trade-offs without hiding failures |
